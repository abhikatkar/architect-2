# 00. Assignment brief

## The ask
Build Architect 2.0: a vibe-coding platform where a user can build an entire agentic application by prompting,
import an existing project, build agents in any framework, connect GitHub, and deploy.

## The key shift
Today's Architect serves non-technical users. Version 2.0 must also serve developers
without losing everything the current product does.

## Judging criteria (as stated, in order)
| Rank | Criterion | Weight | What it means for how I spend time |
|---|---|---|---|
| 1 | Design, UI/UX, flows | Most important | Most hours go to flows, layout, and step-to-step transitions |
| 2 | Feature coverage | High | Every flow exists end to end, even if simulated |
| 3 | Working functionality | Plus points | Only auth + database are real. Nothing else competes for build time |

## Explicit constraints
- First-principles thinking. No copying the current Architect or any competitor UI.
- Minimum feature list: authentication, homepage, chat window, app preview, agent section,
  UI getting built, GitHub integration, deploying the app. "Don't stop at this list."

## Submission also asks
- Why would a non-technical user pick this over Replit, Lovable, or Emergent?
- Why would a technical user pick this over Claude Code, Codex, or Cursor?

These two answers are the product strategy in miniature. See [05-product-strategy.md](05-product-strategy.md).
